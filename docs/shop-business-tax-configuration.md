# 商城经营税务后台

更新：2026-10-02。后台入口：[SnowForce business tax](http://127.0.0.1:9000/app/snowforce-tax-configuration)，使用现有两名商城管理员账号。

## 数据与操作

经营主体、许可核实结果、登记及申报责任审核、运费分类和审核依据保存在现有 Supabase PostgreSQL 的私有 `commerce.store.metadata.snowforce_tax_configuration`。不新增顾客账号，不在前台或公开 Product metadata 放这些资料，也不保存证件号码、税务登录凭据或 API 密钥。

发货地址从原生 `stock_location` 和 `stock_location_address` 读取，关联实际已配置的发货仓库。修改地址继续使用原生后台仓库管理；地址变化后，税务配置必须重新审核。Stripe 经营总部地址另行核实，仓库地址不能自动替代总部地址。

操作分为保存草稿和启用。保存草稿可保留未完成资料，完全不改变付款开关；启用要求资料完整、正式销售主体与当前已发布购买政策一致、仓库完整且属于本店、许可及申报责任和运费处理均已审核，以及管理员的最后一次明确确认。启用还会只读核对当前 Stripe 账户、模式、经营设置及有效加州登记；没有完成登记，不能仅靠勾选确认启用。

运费分类通过商城自己的 Stripe 账户读取官方代码。当前只支持经官方列表核实的 Shipping / Shipping and Handling Combined Charge，默认不选择。两种代码均有适用条件，需要经营者或申报负责人核对实际运费安排和运输成本；不能把名为 Shipping 的费用自动视为免税。说明见 [Stripe 官方分类](https://docs.stripe.com/tax/tax-codes) 和 [现有销售税方案](shop-sales-tax-plan.md)。

## 保存、重试和历史

每条命令带唯一请求 UUID 和期望版本。数据库事务锁定原生 Store；启用时还锁定仓库和地址，重新核对保存的草稿、政策、来源指纹及 Stripe 核对时效。只更新税务配置键，保留原有客服、配送、政策和其他商品设置。Stripe 网络读取在事务外，不在持锁期间等网络。

同一管理员重试同一 UUID 和内容返回原结果，不重复增加版本。改变内容或身份复用 UUID、旧版本或仓库/政策变化均拒绝。网络中断或异常成功响应时，界面锁定编辑，提供原请求重试；确定的冲突保留输入并要求重新载入审核。

启用历史追加保存审核人、数据库时间、经营事实、政策版本、实际仓库地址、完整官方运费分类、Stripe 账户/模式及设置指纹。保存后再改草稿不会自动替换已启用版本。新付款只接受与当前有效审核记录相符的私有报价；已有付款遇到配置变化需要核查，不能用新的资料重算历史实付。历史付款的完整恢复/退款规则还需继续验收。

## 当前实际状态与验证

已通过原生 HTTP 管理接口保存 **revision 1 草稿**：许可、申报责任和运费处理确认均为 false；正式主体和审核依据为空；运费分类为空；实际仓库关联保留；active_revision 为 null。两个指定管理员读取均为 200，匿名访问为 401；尝试启用未确认草稿为 400。没有替经营者确认许可或修改 Stripe 设置。

真实专用数据库角色与证书验证 TLS 的回滚测试覆盖草稿保存、原请求重放、隔离启用、仓库地址快照与行锁、其他 metadata 保留。启用正向案例仅使用隔离 Stripe 读取夹具；整份 Store metadata 回滚后与执行前一致，不是正式审核或真实 Stripe Tax 交易。

实际 React 18 页面测试覆盖空草稿、无默认分类、显式启用审核、成功历史、未知结果原请求重试、异常响应、冲突、缺失政策/地址和官方分类读取失败。完整后台和网站测试、覆盖率、类型检查及构建记录见 [验证记录](shop-verification.md) 与 `output/shop-tax-configuration-*`。

当前 Stripe 仍为测试环境，Tax Settings pending、登记 0，付款确认开关未开启。这一步提供了受控资料来源和报价校验，尚未完成真实报价生产、购物车原子应用、成交税事务、部分退货财务适配、退款税冲销或生产部署。不能把草稿保存或独立启用配置当作收款上线验收。
