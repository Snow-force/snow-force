# 顾客结账与税费报价生命周期

实现和核验：2026-10-02。当前代码已连接顾客结账步骤；这不代表已具备正式上线收款条件。

## 顾客流程

顾客沿用现有 SnowForce 会员登录。商城经营配置实际就绪时，可先填写美国收货地址、选择配送，再点击「计算税费并核对金额」。报价展示商品原价、优惠、运费、消费税、适用政府配送费和准确美元合计。政府费用单独展示，不作为装备商品或包邮门槛金额。

「商城配置就绪」和「本次报价有效」是两个独立状态。没有报价时可以保存地址和配送，但不能付款；税务设置、已审核经营配置、商品分类、已发布政策或付款配置缺失时仍不允许开始结账。后台 GET 只读取数据，不发起 Calculation、清理报价或创建付款。

顾客取得有效报价后，再同意当前配送/退换货政策，进入已有 Stripe 付款流程。付款金额使用私有报价的整数美分。修改地址、配送或商品，以及主动重新报价，都清除前台旧同意状态；操作失败时旧报价不能继续作为可付款金额。未开始付款的报价到期后，界面要求更新；后台再次校验数据库时钟和私有证明，浏览器时钟不是付款授权依据。

已有付款继续冻结地址、商品和配送。只能继续原付款，或通过已实现的只读付款状态恢复流程核实其已取消并退役关联。已在到期前持久建立并绑定的有效付款，遵循已有恢复/完成规则，不被重新报价取代。

## 后台边界

| 接口 | 用途 | 输入和检查 |
| --- | --- | --- |
| `GET /store/snowforce/checkout/:id` | 独立返回经营配置状态、报价状态和本人购物车 | bearer 客户会话、本人归属、实际当前设置；过期的历史金额可供核对，但 `ready:false` 不授予付款权限 |
| `POST /store/snowforce/checkout/:id/edit` | 允许后续原生商品/地址/配送修改 | 只接受空对象；本人归属、两把购物车锁、原生 SQL 行锁及无付款/资金/订单证明；不要求当前税务开关开启 |
| `POST /store/snowforce/checkout/:id/quote` | 归一化、固定请求计算、原子应用并重新核对报价 | 只接受空对象；前端不能指定金额、税码、经营事实、供应商身份或购物车归属 |

报价编排使用独立的短期互斥键；各子步骤继续使用原结账锁和原生购物车锁，避免嵌套获取同一把锁。有效且剩余时间超过 60 秒的当前报价直接复用，不新增 Calculation 或写入。

修改前，清理服务在一个 SQL 事务内核对签名和不可变私有证据、逐项原生金额、税行、费用属性及资金状态。只软删除本次证明的税行和政府费用，移除购物车报价/政策引用；原商品和所有 operations、quotes、applications、历史 collection/session 保留。税行数量、条件写入、最终核对或锁租约失败时全部回滚。

原生 HTTP 和已锁定工作流的校验点都会拒绝直接修改带报价的购物车。清理与原生修改是两个步骤：若其他窗口在间隙应用新报价，工作流再次拒绝修改，要求重新核对；不会携带旧税费继续修改。

供应商 POST 结果未知的 pending 请求阻止编辑。报价重试直接复用已保存的请求身份和参数，不在重试前修改来源；已过期且未解决的请求仍需人工核查，代码不会猜测其结果或覆盖证据。已经应用过的历史报价不能被重新预留为新应用，清理后重新报价会建立新操作和应用记录。
