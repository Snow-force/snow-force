# 购物车税费原子应用

更新：2026-10-02。私有服务已实现并通过真实数据库最终回滚验证。它把税行、独立政府费用、私有应用记录和签名引用一起保存，失败则一起回滚。**尚无顾客可调用的报价应用路由，不能据此上线收款。**

## 如何调用与保存

`services/commerce/src/lib/tax-quote-application.ts` 的 `applyCartTaxQuote` 只接受已验证 customer 身份、本人购物车 ID、私有报价 UUID 和取消信号；价格、税码、金额和许可确认均从服务端读取。它使用与结账相同的两把购物车锁，重新读取当前来源和不可变报价，核对账户/模式、配置版本、商品审核、地址、数量、优惠、配送及到期时间。

数据继续保存在现有 Supabase PostgreSQL 的私有 commerce schema，顾客仍使用现有 Supabase 登录。应用在单一 SQL 事务中完成：

1. 锁定经营和商品来源表、未付款购物车/地址/商品/优惠/配送/支付关联及现有税行，重新读取同事务里的原生记录。
2. 复核经营资料、商品分类、配送规则和 region；已有订单、会话、资金、原生 credit line、未解决税务请求或过期报价均拒绝。
3. 已验证空且无资金的 payment_collection 只解除其购物车关联，保留集合完整记录；退役旧税行，写入报价对应的商品/运费税行及独立政府费行。
4. 使用安装版本原生金额引擎重新计算。逐项和整单均匹配后，保存 snowforce_tax_quote_applications，并只更新 cart.metadata.snowforce_tax_quote；其他 metadata 保留。
5. 提交前再次检查数据库时间、设置新鲜度、开关和锁信号。相同有效报价的重复调用验证现有私有证据后返回，不重复写入。

来源表使用 SHARE 锁防止事务内发生修改或新增来源行，锁等待上限 5 秒。事务中没有 Stripe、承运商或其他网络请求。这会短暂阻塞相关后台写入；生产并发、锁等待和吞吐量尚未验收。

## 原生税率精度

Medusa 原生税表使用 PostgreSQL REAL，原生金额引擎按百分比计算且不逐行四舍五入。当前 Shared pooler 的 extra_float_digits=0，还会将税率输出为六位有效数字。只在内存中验证双精度计划不能代表真实存储行为。

计划先按 float4 映射税率；核验只接受这一特定存储税率的可往返表示或 PostgreSQL 六位有效数字表示，再用实际读到的税率复算原生金额。每个原生计算结果必须与这次具体运算一致，并且四舍五入后的美分必须与不可变报价完全相同；整单也独立核对。多个商品的存储误差若累计改变整单应付美分，整笔应用拒绝并回滚。

原商品单价、规范化优惠、运费、政府费用和 Stripe 金额仍严格要求整数美分。法定税率、辖区和税务理由保留在原 Calculation，原生映射率只服务于金额表达。此次没有修改数据库精度设置、原生表类型或依赖。

## 独立政府费用与包邮

报价中合法适用的 CO/MN Retail Delivery Fee 使用数量 1、无商品/规格关联、不参与库存、不可优惠、无需配送、无税行的 custom item。核对费用标记、金额、类型和原生属性之后，还必须有私有报价、应用记录和有效签名；顾客自行填写 metadata 或 custom line 不能通过。

已将私有费用校验接入商品分类及配送金额读取。包邮依据不可变报价中的优惠后未含税商品金额，排除政府费用。例如测试中商品 US$99.99、政府费用 US$0.28，仍收 US$9.95 运费，不能因为原生商品小计超过 US$100 而包邮。这些测试税费数值是隔离样例，不是商店正式税率。

费用在订单/会员投影和后台的独立展示、普通退换货排除、完整库存与发货流程仍须接入和验收。过期已应用报价的安全清理、重报价及编辑流程也尚未实现；目前停止继续付款，不能用移除标签或删除私有记录绕过。付款集合/session 还须使用已验证报价的整数美分统一金额；现有付款创建会严格拒绝原生税率运算产生的小数美分 total，这道付款检查没有放宽。

## 验证证据与限制

- 真实 snowforce_commerce 角色和验证 CA 的 TLS 下，实际 SQL 行锁/来源表锁、税行、费用、签名及私有记录通过最终 ROLLBACK 验证。最后一步失败后没有残留税行、费用或应用；成功后复用零写入，费用不改变包邮商品金额。
- 测试购物车、客户、优惠、配送、税行及全部私有报价记录最终为零，完整 Store metadata 摘要与测试前相同。证据：output/shop-tax-application-database-rollback.json。
- 实际 Medusa Query 接受 50 个来源字段及税率/费用属性字段，缺失购物车返回空结果；商品仍为 14 草稿。证据：output/shop-tax-application-native.json。它只验证查询计划，正向 SQL 核验使用隔离的经营审核、graph 关联、customer actor、锁租约及供应商替身。
- 实际 Stripe 单独 GET 核对仍为 test/pending/0 registrations，付款开关关闭。没有真实 Calculation、收款、订单、库存预占、发货、退换货或退款端到端验收，没有永久业务写入、迁移、权限变更或部署。

完整测试、覆盖率、构建与 HTTP 可用性记录见 [验收记录](shop-verification.md)。下一步是接入顾客报价编排及过期/编辑恢复，再实现捕获后的成交税账、持久重试任务、部分退货财务适配和实际退款后的税冲销；生产服务和真实 Sandbox 全流程仍需完成，见 [上线清单](shop-launch-status.md)。
