# 首页新人商城优惠

访客进入首页时立即打开可关闭的注册优惠弹窗。关闭后仍可从首页优惠条重新打开。已登录会员不显示注册弹窗。复用现有注册、隐私同意及邮箱验证流程；验证成功后在 `/member/welcome` 或会员首页自动领取个人折扣码。

个人折扣码随一封中英文欢迎邮件发送至首次领取时的已验证注册邮箱，邮件包含九折规则、有效期及商城入口。验证回调、确认邮箱、登录及完成隐私同意后的服务端流程自动领取并加入队列，不依赖领码页面或浏览器脚本执行。重复登录、打开会员页或重复领取不会再次发信。尚未验证邮箱的账户不会收到欢迎折扣邮件；邮箱验证邮件仍由 Supabase 单独发送。

新人优惠固定为 10%（九折）、无最低消费，仅限原价商品，不与其他促销叠加。折扣码由会员身份稳定生成，绑定商城客户，只能使用一次。独立领取记录同时限制账户、商城客户和规范化后的已验证邮箱（去掉首尾空格并转小写，不合并邮箱别名）。记录不随账户或原生优惠删除而清除，同一邮箱重新注册不能再次领取。每人一次是活动条款；系统按账户及验证邮箱校验，无法识别同一人持有的多个不同邮箱。重复领取不会更换折扣码或延长有效期；删除优惠不会重新发码。每个码使用商城原生 Promotion 与 Campaign，管理员可在现有商城 Promotions 页面查看或停用。

## 启用前配置

经营者已确认领取后有效期为 **30 天**。发件身份共用 `SnowForce <noreply@notifications.snow-force.com>`，回复地址使用商城 `shop@snow-force.com`，不使用活动联系地址。

折扣及使用范围已确认；后台已准备 30 天有效期及 `2026-10-11T05:00:00Z` 的新账户资格起点（洛杉矶 10 月 10 日 22:00）。配置须发布后才生效，代码默认关闭。先应用 `20261011025512_newcomer_email_limits.sql` 迁移，再在商城后端设置以下变量并重新发布：

| 变量 | 内容 |
| --- | --- |
| `NEWCOMER_ENABLED` | `true` 启用 |
| `NEWCOMER_DISCOUNT_TYPE` | 固定 `percentage`，可省略 |
| `NEWCOMER_DISCOUNT_VALUE` | 固定 `10`，可省略；其他值会使配置无效 |
| `NEWCOMER_MINIMUM_USD` | 固定 `0`，可省略；不设最低消费 |
| `NEWCOMER_VALID_DAYS` | 从第一次领取开始计算，1–365 天 |
| `NEWCOMER_ELIGIBILITY` | `new_accounts`：指定上线日期后注册且尚未下单；`no_orders`：所有尚未下单的账户 |
| `NEWCOMER_REGISTERED_AFTER` | `new_accounts` 必填，上线时间，UTC ISO 日期，例如 `2026-10-11T00:00:00Z` |
| `NEWCOMER_SIGNING_SECRET` | 两端共用的独立随机密钥，至少 32 字符，不使用邮件推广密钥 |

## 欢迎邮件配置

先应用 `20261011030617_newcomer_welcome_emails.sql`。欢迎信使用独立持久化队列，复用已有 Resend 投递适配器，不能使用旧邮件适配器的控制台成功回退。后台设置：

| 变量 | 内容 |
| --- | --- |
| `NEWCOMER_EMAIL_ENABLED` | `true` 开启欢迎邮件 worker，默认关闭 |
| `NEWCOMER_RESEND_API_KEY` | Resend 服务端密钥；省略时复用 `MARKETING_RESEND_API_KEY` |
| `NEWCOMER_EMAIL_FROM` | 已验证域名的发件人，例如 `SnowForce <welcome@your-domain>`；省略时复用 `MARKETING_EMAIL_FROM` |
| `NEWCOMER_REPLY_TO` | 联系邮箱；省略时复用 `MARKETING_REPLY_TO` |
| `SNOWFORCE_STOREFRONT_URL` | 正式网站 HTTPS 地址 |
| `MARKETING_POSTAL_ADDRESS`、`MARKETING_UNSUBSCRIBE_SECRET` | 邮件页脚及退订入口的已有配置，密钥至少 32 字符 |
| `MARKETING_SENDS_PER_MINUTE` | 与活动/商城推广共用的每分钟发送预算，默认 30，范围 1–120 |

欢迎邮件 worker 每分钟检查队列，单次最多处理 10 封；关闭邮件功能或配置不完整时保留队列、不调用邮件服务。领取页区分待发送、已提交发送和无法发送，并始终保留可复制的折扣码。一次性发放用户领取的新人权益，不自动订阅后续推广；永久退信或投诉地址不会再投递。邮件本身保留联系地址和推广退订入口。

网络超时和临时服务错误自动退避重试，冻结第一次投递的内容、收件人和发送标识；超过 23 小时仍无法确认的请求进入 `attention`，不会自动重新发送。依据 [Resend 发送标识文档](https://resend.com/docs/dashboard/emails/idempotency-keys) 保持在其 24 小时缓存窗口内。已接受的邮件不会再次入队。退信和投递反馈沿用[邮件推广 webhook 配置](marketing-email-operations.md)，可处理重复回调及早于发送结果到达的事件。工作人员应核实 `attention` / `failed` 记录对应的 Resend 实际结果，再决定后续操作，不直接清除记录重发。

网站端仅需同一个 `NEWCOMER_SIGNING_SECRET`，沿用已有 `MEDUSA_BACKEND_URL` 和 `MEDUSA_PUBLISHABLE_KEY`。密钥不得使用 `NEXT_PUBLIC_` 前缀。配置完整且明确启用时，注册弹窗及验证用户领码可以在商城管理模式下开放；此时只允许经过现有 customer 身份认证的客户关联和新人码领取，不开放购物车、支付、结账或订单操作。实际兑换仍须通过既有销售、税务和付款门槛。配置缺失或服务不可用时首页正常展示，不打开优惠弹窗。

网站只签名经 Supabase `getUser()` 验证的会员 ID、已验证邮箱和账户创建时间，后端还将该 ID 与客户 JWT 对应的不可变 Supabase provider identity 比对。客户不能提供其他人的身份、价格或折扣金额。领取不依赖邮件营销订阅。

个人新人码的原生应用方法必须保持 percentage / 10 / items / each / USD 和一次使用上限。后台修改为固定金额、其他比例或其他应用范围后，领取、购物车应用和兑换均拒绝该码，不会继续显示或使用错误的折扣规则。通用 `SNOWFORCECLUB` 促销不属于个人新人码；其折扣类型已在原生后台纠正为 10%，既有商品范围及总使用上限保留。

## 使用与结账

会员可以复制自己的折扣码，在购物车输入或移除，实际金额由商城原生规则计算。优惠仅适用于美元计价原价商品，不抵扣运费或税费。购物车同时有原价和特价商品时，仅原价商品享受九折。原生促销计算使用服务端商品价格及 `compare_at_unit_price` 筛选，非可折扣项目也被排除。其他优惠码和自动促销不能与新人优惠一起结账；付款前和订单完成时再次检查实际促销调整及九折金额上限，覆盖直接调用原生接口的情况。

任何优惠码变动先通过现有购物车编辑边界清理旧税费报价。支付已经开始时须先通过原有恢复流程确认远端支付安全，再编辑购物车。原生优惠修改 workflow 也验证编辑边界，覆盖绕过网站的直接请求。

创建付款前通过 PostgreSQL 原子更新，将新人优惠预留给唯一购物车；支付完成 workflow 再次核验，覆盖原生接口和支付 webhook。两个已加优惠的购物车不能分别兑换同一个码。新的付款必须在优惠有效期内开始；已经合法开始的同一购物车付款可以在优惠到期后完成，避免扣款后无法生成订单。失败后可以继续同一个购物车；为了避免重复兑换，首次尝试付款后不能把该码转移至另一个购物车。需要客服处理的情况应先核验原购物车付款及订单，不直接清除预留字段。此限制不影响普通促销码。

停用新人功能停止展示与发码；已经发出的原生优惠须在商城 Promotions 中停用才能撤销。新人优惠比例和门槛不能通过环境变量更改；调整有效期只影响后续发码，已发码保持原到期时间。欢迎邮件发送不消耗折扣码次数；真正兑换仍由商城付款和订单流程控制。当前功能不接入广告平台，也不自动部署。
