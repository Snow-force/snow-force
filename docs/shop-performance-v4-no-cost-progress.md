## 生产观测入口已核验

Railway 会将应用输出的 JSON 提升为结构化 `attributes`，对应日志的 `message` 可以为空。此前按自由文本 `snowforce.shop_performance` 搜索零条，不能据此断定埋点失败。

正确读取方式：

1. `get_logs` 使用当前 Web 服务、生产环境、明确 UTC 窗口和 `types: ["deploy"]`。
2. 过滤表达式使用 `@event:snowforce.shop_performance`；按单次操作查找用 `@operationId:<uuid>`。日志进入平台有延迟，HTTP 204 后不能立即将一次零结果当作丢失。
3. 将每条返回的 deploy 记录写为一行 JSON，再交给 `node scripts/shop-performance-summary.mjs <observations.ndjson>`。工具现在同时识别原始事件和 Railway 属性记录，并跨两种表示去重；不导出无关日志属性。
4. 先区分诊断样本与真实业务，再按版本、场景、端点、网络、视口和预热组分析。成功、拒绝、超时和缺失终点均需保留。样本不足不宣布 p95 达标。
