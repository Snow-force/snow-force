# 顾客购买条款与退换期限

更新：2026-10-02。会员订单详情的“退货与换货”区域新增购买时政策与日期显示。

## 显示内容

- 购买时政策版本、正式销售主体、当时的客服联系方式，以及原配送、商品条件、运费、退款、退货地址和消费者权利双语文案。
- 普通退换货的日历天数和各商品的申请截止日，按太平洋时间计算。分批送达显示已知截止日期范围，不推测顾客退回哪一批。
- 已批准申请的交运截止日。页面明确提示需核对承运商实际接收凭证，填写追踪号不代表已交运。
- 超出普通期限仍可提交审核；质量问题和错发不会被页面自动拒绝。无法核实原购买条款或送达日期时，提示客服核查，不假定 30 天/14 天或套用最新政策。

## 数据与权限

沿用本人订单的售后读取接口，不新建表或更改权限。后端先通过原生订单查询过滤 customer_id，并核对已验证 Supabase Auth 身份的原生关联；随后验证订单政策 HMAC、真实 order_cart、购买时序和准确发布历史。顾客只收到公开政策内容及日期投影，不包含签名、原始 cart/Store metadata、内部审核备注、凭据或管理员资料。

一次读取只解析一次原购买政策。批准后期限只来自有效原政策和时间一致的审核记录，不以原生退货创建或追踪号更新时间替代。新政策发布不缩短旧订单期限。这个显示不改变原后台审批：普通超期/缺证申请仍需显式例外与原因；质量/错发仍按实际情况审核。

主站严格验证返回字段、有效日历日期、截止日期状态、请求 ID 和订单归属。旧后台尚未提供 purchase 字段时显示待核查状态，不阻止其余订单内容。切换订单时售后组件按订单 ID 重建，避免保留上一订单的请求或购买条款。

## 验收与限制

隔离测试覆盖历史版本保留、新版本期限缩短、失效签名/缺失记录、审批时间矛盾、隐私投影、错误订单和不合理日期。实际 React 组件验证中英文条款、历史邮箱、完整文案、分包日期、超期仍可申请、交运证据提示及切换订单清理。

专用数据库角色已通过验证 CA 的 TLS，只读执行原订单关联与政策查询，确认没有原记录时返回人工核查且不生成期限。数据库仍为 0 订单/申请，因此真实历史订单、顾客登录、送达与承运商证明的端到端验收尚未完成。没有金融操作、政策发布或商品发布。

证据前缀：`output/shop-purchase-terms-`。所有正常测试、覆盖率、类型检查与构建结果记录于 [商城验证记录](shop-verification.md)。
