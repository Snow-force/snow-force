# SnowForce 商城合伙人操作指南

适用人员：负责商品、分类、价格、库存及客服的合伙人。版本：2.0，2026-10-10（洛杉矶时间）。按当前部署、后台操作界面和经营者已确认的条件更新。

**商品浏览和动态导航已上线。正式收款仍未开启；实际订单收款、资金退款及税务经营需负责人完成启用与验收后开展。** 本指南中的订单与退款步骤用于交接，不代表正式资金操作已经开放。

日常新增分类、子分类、品牌和精选集合，可以在 Medusa 后台完成。保存后，前台下一次加载读取后台数据，无需修改代码或重新部署网站。

使用登录页 **Forgot password / 忘记密码** 提交恢复申请，检查收件箱及垃圾邮件。恢复邮件的实际送达仍需在使用者自己的邮箱确认。没有收到时，请负责人通过已登录的管理员恢复功能处理；不重复创建同名账号。

后台已提供密码恢复功能，恢复链接为短期、单次使用的私密链接。不要把链接放进群聊、截图或指南。登录失效时重新登录，再回到原记录确认上一笔修改是否保存。

## 3. 商品、规格、图片和售价

### 编辑已有商品

1. 在 **Products** 搜索英文名称、Handle 或 SKU，打开商品，先核对实物型号、照片和颜色。
2. 编辑 **Title** 和 **Description**，填写核实过的材质、用途、规格及保养说明。说明中的尺寸必须与 Variant 选项和 SKU 一致。
3. 在 **Media / Thumbnail** 上传并选择正确图片，调整封面及顺序；保存后重新打开，确认图片仍存在。
4. 在每个 **Variant** 核对颜色、尺码、唯一 SKU 和 USD 售价；在 Inventory 核对同一 SKU 的 Irvine 库存。
5. 保存后刷新前台，选择同一规格，核对名称、照片、价格及有货状态。编辑草稿不会让草稿商品公开出现。

### 新建商品

先用 **Products → Create** 保存为 **Draft**，填写稳定且唯一的 Handle。添加实际可售的 Color / Size 等 Options，再为每个真实有售组合建立 Variant；只有选项名称不会自动形成可售规格。

为每个规格填写唯一 SKU、USD 价格，开启 **Manage Inventory**，关闭 **Allow backorders**，关联正确销售渠道、配送配置和 Irvine 库存。实物或规格未确认时保持草稿，不用虚拟库存代替待到货商品。

### 美元价格与中文资料

| 内容 | 操作与核对 |
| --- | --- |
| 普通售价 | 输入美元金额，最多两位小数。例如 $129.00 填 `129.00`，不是美分数字 `12900` |
| 税费 | 按未含税售价维护，不自行把销售税加进商品价格；税务分类由指定负责人审核 |
| 历史订单 | 后续改价不改变已下单订单的原始成交金额 |
| 商品中文标题、描述及颜色翻译 | 当前原生表单不能完整编辑现有双语对象；将确定的文字交给技术人员，不把 JSON 粘成普通字符串 |
| 分类与集合中文名 | 可直接在各自“商城展示 → 中文名称”编辑，无需技术人员 |
| 页面版式 | 首页布局、颜色和按钮样式仍属于网站开发范围 |

图片必须能公开加载。分类或集合的展示图填写可公开访问的 **HTTPS URL**，不能使用本机路径、需要登录的地址或临时授权链接。商品图片保存后要在前台实际打开检查。

## 4. 动态分类与多列导航

前台固定显示八个导航栏目：**FEATURED、MEN、WOMEN、KIDS、SKI & SNOWBOARD、ACCESSORIES、BRANDS、SALE**。栏目下的内容来自后台分类、集合、品牌和优惠数据；旧的四个固定品类已不再作为日常分类维护入口。

| 分类类栏目 | 后台组织示例 | 前台效果 |
| --- | --- | --- |
| MEN | Men → Jackets / Pants | 男士栏目下显示实际创建的子分类 |
| WOMEN | Women → Ski Suits | 女士栏目及雪服分类页 |
| KIDS | Kids → 按实际商品新增子分类 | 儿童栏目内容随分类维护 |
| SKI & SNOWBOARD | Ski & Snowboard → Skis / Snowboards | 双板与单板栏目及分类页 |
| ACCESSORIES | Accessories → Bag & Backpacks / Hats | 配件栏目下的多列子分类 |

表中 Jackets、Pants、Snowboards 是组织示例，只有在后台实际创建后才会出现。当前已部署的子分类包括 Ski Suits、Skis、Bag & Backpacks 和 Hats；不需要为了让栏目看起来完整而建立没有业务用途的分类。

### 新增子分类：以 ACCESSORIES 下的 Goggles 为例

1. 打开 **Categories → Create**，填写名称 Goggles 和唯一、稳定的 Handle。
2. 设置分类为 **Active** 和 **Public**。Internal 或不活跃分类不应作为公开导航使用。
3. 在分类排序/组织界面 **Organize ranking**，把 Goggles 放到 Accessories 下面，保存父子关系。
4. 打开新分类详情。在 **商城展示** 填中文名称“雪镜”，需要时填写 HTTPS 展示图，再点 **保存展示 / Save merchandising**。
5. 在分类详情的 **Products** 区域打开操作菜单，选择 **Add**，勾选属于该分类的商品并保存。
6. 刷新前台，展开 ACCESSORIES，点击 Goggles，检查分类标题、商品、图片、规格价格及有货状态。

分类创建和商品关联是两个操作。只创建分类，商品不会自动归类；关联的 Draft 商品也不会因此公开发布。一个商品可以按实际用途关联多个分类。

### 顶级分类的栏目与排序

**导航栏目 / Navigation section** 只对顶级分类生效，子分类跟随父分类。常规顶级名称可使用 **自动 / Automatic**；名称特殊或需要明确归属时，在顶级分类展示区选择 MEN、WOMEN、KIDS、SKI & SNOWBOARD 或 ACCESSORIES。

要调整分类显示顺序，在 Categories 的排序/组织界面调整并保存。不要靠反复改名排序，也不要随意修改已发布 Handle，以免旧链接失效。移动父分类会影响其下全部子分类，保存前先核对目标栏目。

### 保存结果与两人协作

显示 **已保存 / Saved** 后刷新前台。显示 **数据已变化，请重新加载 / Data changed** 时，先重新加载核对另一人的修改，再编辑。显示保存结果未知时使用 **重试保存 / Retry save**，它会复用同一内容；不要立即创建重复分类。

## 5. FEATURED、BRANDS 与 SALE

### FEATURED：用 Collections 管理精选

1. 打开 **Collections**，创建或编辑集合，例如 New Arrivals 或 Winter Essentials，填写名称和稳定 Handle。
2. 在原生商品关联区添加对应商品，并检查商品已具备发布条件。Medusa 原生商品的集合归属按其单一 Collection 字段管理；不要把它当作可任意多选的分类。
3. 在集合详情的 **商城展示** 填中文名称及需要的 HTTPS 展示图，将导航栏目选为 **FEATURED / 精选**。
4. 填 **展示顺序 / Display order**，使用 0-10000 的整数，较小数字排在前面；点击保存展示。
5. 刷新 FEATURED 菜单，打开集合页核对商品。暂不展示在菜单时选择 **从导航隐藏 / Hide from navigation**。

从导航隐藏仅控制菜单，不等于商品下架或限制已有直达链接。要下架商品，请修改商品状态。

### BRANDS：在商品中填写品牌

打开 **Products → 商品详情 → 商城展示 → 品牌 / Brand**，填写实物真实品牌并保存。前台按已发布商品的品牌数据生成 BRANDS 菜单及品牌筛选，不需要再改导航代码。

同一品牌统一拼写、空格和大小写，避免形成多个条目。未核实品牌时不要从商品标题猜测。当前 BRANDS 为空是已发布商品尚未填写品牌数据；填写并保存后再核对显示。

### SALE：集合展示、促销价和优惠规则分别维护

| 需要的效果 | 后台操作 | 不会自动完成的事 |
| --- | --- | --- |
| SALE 菜单中的专题 | Collections 的导航栏目选 SALE | 不会自动给集合内商品打折 |
| 指定商品的促销售价 | Price Lists 设置商品、USD 价格和有效条件 | 不会自动建立优惠码 |
| 优惠码或自动折扣 | Promotions 设置状态、适用规则、日期和限额 | 不会自动把商品放进 SALE 集合 |
| 在集合展示公开优惠码 | 集合展示区填 Promotions 中已有的 code | 不会新建促销，也不代表所有购物车都符合条件 |

只展示已经启用、在有效期内且未用尽的关联促销码。最终折扣资格和金额由购物车验证。不得把 SALE 标签当作实际优惠，也不得虚构原价。

促销发布前检查适用 SKU、顾客范围、最小金额、日期和使用次数，以及优惠后金额是否影响 $100 包邮门槛。正式付款未开放时可准备规则和核对展示，实际会员购物车及支付金额验收须在开放前完成。

## 6. 入库、补货与盘点

| 库存字段 | 意思 | 操作注意 |
| --- | --- | --- |
| In stock | 仓库登记的库存总量 | 与正确 SKU 的实物核对 |
| Reserved | 已被订单或预留占用的数量 | 不为显示有货而清除 |
| Available | 简单单件商品的该位置库存减预留 | 前台可售状态还受渠道等配置影响 |

1. 在 **Inventory** 搜索 SKU，核对颜色、尺码和实物，打开 **Irvine** 的库存行。
2. 核对当前总量、预留和待发订单。缺少仓库关联时请负责人处理，不把其他仓库的货算进 Irvine。
3. 打开 **Adjust inventory**，再次确认仓库与 SKU。当前 **In stock** 填调整后的总量：原有 10 件、新入库 5 件，应填 `15`。
4. 保存，重新读取 In stock / Reserved / Available，记录数量变化、原因、日期和操作人。

报损与不可再售退货不计入可售库存。退货优先走原生退货收货流程，核对系统是否已回补，避免再手工加一次。关闭 Allow backorders，不用超卖掩盖缺货。

## 7. 运费、地址与销售政策

以下为经营者已确认的经营条件。**当前销售政策仍为草稿，须负责人正式发布后对顾客生效；历史订单按下单时保存的条款处理。**

### 运费与配送

在 **SnowForce shipping** 查看已有配送方式，修改 **Base shipping (USD)** 和 **Free shipping from (USD)**，保存后重新载入。日常变更需负责人确认并同步政策。

| 项目 | 已确认条件 |
| --- | --- |
| 商品优惠后、未含税金额满 $100 | 免标准运费 |
| 商品优惠后、未含税金额低于 $100 | 标准运费 $9.95，仅配送费用 |
| 门槛不计入 | 运费、销售税及政府配送费用 |

| 项目 | 已确认条件 |

商品税码、运费税务审核和税务经营配置由指定负责人管理；不得为消除页面提示而勾选“已审核”。持续经营许可的更新另由经营负责人跟进。

## 8. 发布、下架与前台核对

商品浏览已连接 Medusa。完成以下检查并经负责人确认后，可以从 **Draft** 改为 **Published**，发布商品展示；这不会自动开启付款。需下架时改回 Draft，保留商品与历史记录。

- [ ] 实物、型号、说明、照片与颜色/尺码一致，没有待确认参数。
- [ ] 每个可售规格有唯一 SKU、正确 USD 售价及 Irvine 实际库存。
- [ ] Manage Inventory 开启，Allow backorders 关闭，销售渠道和配送关联正确。
- [ ] 分类 Active / Public，父子关系正确，商品已关联到正确分类。
- [ ] 需要的品牌、集合栏目、中文分类名和展示图片已保存。
- [ ] 商品税务资料的审核待办已交给指定负责人；正式交易启用前完成。
- [ ] 发布后在前台选择每个规格，核对图片、价格、有货状态及所属分类。

### 保存了但前台没有变化

| 现象 | 按顺序检查 |
| --- | --- |
| 菜单没有新子分类 | 是否 Active / Public、父分类是否正确、顶级导航栏目是否正确、保存是否成功；刷新页面 |
| 分类页没有商品 | 是否已做 Products → Add；商品是否 Published；销售渠道及规格配置是否正确 |
| BRANDS 没有条目 | 已发布商品是否在专用品牌字段填写并保存；品牌拼写是否统一 |
| 价格或有货状态不对 | 前台选择的 SKU 是否与后台相同；USD 价格、Irvine 库存和预留是否正确 |
| 优惠没有生效 | 集合栏目不能代替促销；检查 Promotions / Price Lists 的状态、日期、条件与使用限制 |
| 图片不能打开 | 是否使用公开 HTTPS 图片；重新打开后台与前台确认，不重复上传一批同名图片 |

仍异常时记录 Handle、SKU、菜单位置、时间、提示和已做操作，交给负责人。不要用重复创建商品或绕过资金开关解决问题。

## 9. 订单、退换货与退款

**本节实际资金操作须在负责人确认正式交易启用后开展。** Sandbox 已完成支付、退款及税务冲销的 API 联调；完整会员浏览器购买与正式经营验收仍待完成。培训使用明确的测试环境和练习数据，不用真实订单试验。

### 订单资金与发货

在 **Orders** 核对订单编号、会员、收货地址、SKU、数量和资金状态。**Authorized** 是授权状态，**Captured** 才是已捕获款项；不要把支付授权当作已收款。

系统采用原订单单次完整捕获，由指定资金负责人按实际订单处理，不自行分次捕获。建立正确商品的履约记录，购买面单、包装并实际交运后保存 **Shipment**、承运商和追踪号。承运商或可靠记录确认送达后才标记 **Delivered**；打印面单不代表送达。

### 处理退换货申请

1. 打开 **SnowForce returns**，选择申请，核对原订单、送达记录、适用政策版本、原因、SKU 和申请数量。
2. 写顾客可见的回复与内部备注，按核实结果点 **批准并发送指引 / Approve** 或拒绝。回复保存到顾客订单页面，不等于客服邮件已经发出。
3. 普通超期申请若确需例外，填写具体理由并由负责人审核；质量、错发等问题结合适用权益处理，不机械套用个人原因期限。
4. 在原订单创建正确的原生 **Return / Exchange**，回到售后页点击 **刷新关联选项 / Refresh options**，选择对应操作并 **关联处理记录 / Link operation**。
5. 实际收到商品后，在原生流程登记收到的 SKU、数量和状态。确认可再售库存处理结果，避免重复手工回补。

批准申请不等于已收到退货，也不等于已退资金。换货还需按正确替换规格履约，并核对实际送达。

### 退款预览与实际退款

在处理中的申请里使用 **原始成交退款预览 / Original sale refund preview**，填写实际收到、可退的商品数量。系统按原订单优惠后金额和税费计算，不按今天的商品售价退款。

| 页面操作 | 实际作用 |
| --- | --- |
| 退回原始运费和运费税 | 仅在政策及审批允许时勾选，不是每次退货默认勾选 |
| 保存退款预览 / Save refund preview | 保存待核对金额与分配记录，尚未向顾客退款 |
| 核对 Stripe 款项 / Check Stripe funds | 核对实际资金状态，不会发起新的退款 |
| 确认金额并执行退款 / Issue refund | 开关启用后才可用；指定负责人确认后会发起真实退款 |
| 核对并完成 / Verify and complete | 核对收货、资金、原生退款账本、税务冲销及换货履约等条件；未齐备则保持处理中 |

保存预览后核对商品、商品税、运费和运费税等分项。若页面要求政府配送费用的处理说明，填写审批依据，不跳过必要理由。当前正式环境显示 **资金退款执行尚未启用**，不得绕过限制到 Stripe 再退一笔。

正式退款开放后，资金负责人勾选金额确认并执行。处理中、结果未知或待重试时，保留原退款记录，先刷新并核对 Stripe 款项，不新建重复退款。顾客回复应如实区分“已批准”“处理中”“已发起退款”；资金与相关处理核对完成后才标记完成。

税务交易记录与退款冲销不等于已经申报或缴税；申报由税务负责人另行处理。
