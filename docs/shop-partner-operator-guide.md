## 3. 编辑商品和准备新品

### 3.1 编辑一款已有草稿

1. 在 **Products** 搜索商品英文名称或 Handle，打开商品。
2. 核对商品照片、实物型号和颜色，确认没有选错。
3. 编辑 **Title**（英文名称）和 **Description**（英文说明），填写实际核实过的材质、用途、保养和功能。
4. 保存，重新打开该商品确认内容保留。现阶段保持 **Draft**。
5. 涉及颜色、尺码或库存时，继续按下方步骤逐个规格核对。

**中文资料当前不能在原生表单中完整编辑。** 现有中文名称、描述和颜色翻译存为双语对象或数组，原生 Metadata 表单会锁定这些内容。需要把明确的中文文字交给技术人员维护；不要把 JSON 文本粘成普通字符串。没有中文资料时，中文前台可能回退显示英文。

### 3.2 准备一款新品

1. 在 **Products** 点击 **Create**，填写英文标题、说明和稳定唯一的 **Handle**，先保存为草稿。
2. 设置实际可售的 **Options**：颜色 Color、尺码 Size。
3. 对每个实际有售的颜色与尺码组合建立 **Variant**，填写唯一 SKU。
4. 每个 Variant 填写正式 USD 售价，开启 **Manage Inventory**，关闭 **Allow backorders**。
5. 在 Inventory 关联实际 Irvine 仓库，登记实物数量。
6. 由负责人确认商品销售渠道、配送配置和商品税务分类都正确。
7. 按第 7 节核对，现阶段仍保持草稿，待整体上线完成后由负责人确认发布。

只有 Color / Size 选项不会自动产生可售商品规格。没有实物的组合不创建；不要将待确认规格当成可售库存。

## 4. 修改美元售价

1. 在 **Products** 打开正确商品，找到具体颜色、尺码及 SKU。
2. 在规格或价格编辑区修改 **USD** 价格，使用美元金额，最多两位小数。
3. 例如需要售价 US$129.00，输入 `129.00`；不要输入美分数字 `12900`。
4. 保存并重新打开，核对 SKU、币种和金额。
5. 商品已发布且上线验收通过时，到前台选择同一规格，检查价格实际一致。

商品售价按未含税美元填写，不自行把销售税加进价格。已下单订单按原价格和优惠处理，不因修改当前价格而重算。

首次运营先维护正常售价。**Price Lists / Promotions** 属于促销配置，需负责人确认适用范围、时间和计算结果，并单独验算包邮及税费后使用。

## 5. 入库、补货和盘点

### 5.1 先认清三个数量

| 页面名称 | 意思 | 注意 |
| --- | --- | --- |
| In stock | 仓库登记的库存总量 | 盘点时与正确 SKU 的实物核对 |
| Reserved | 已被订单或预留占用的数量 | 不为让前台显示有货而清除 |
| Available | 该位置简单单件商品的库存减预留 | 顾客可购买数量受这个数影响 |

### 5.2 补货或调整数量

1. 在 **Inventory** 搜索 SKU，核对商品规格，打开 Irvine 仓库库存行。
2. 核对实物、当前库存和待发订单占用。没有仓库行时请负责人协助关联实际发货仓库。
3. 打开 **Adjust inventory**，再次确认仓库和 SKU。
4. 当前原生窗口的 **In stock** 填的是调整后的总量。例如原有 10 件，新入库 5 件，应填 `15`，不是 `5`。
5. 保存，重新核对总量、Reserved、Available，记录调整原因和时间。

不要把另一仓库库存算成 Irvine 现货；不要开启 Allow backorders 掩盖缺货。报损商品不计入可售库存。退货入库优先走原生退货收货流程，避免系统已回补后又手工增加一次。

## 6. 运费、配送和客服信息

### 6.1 统一运费与包邮

进入 **SnowForce shipping**，选择已有配送方式，编辑以下美元字段，再点击 **Save / 保存**，重新载入核对。

| 字段 | 已确认设置 |
| --- | --- |
| Base shipping (USD) | `9.95` |
| Free shipping from (USD) | `100.00` |
| 包邮判断 | 优惠后、未含税商品金额满 US$100 |

运费、销售税及政府配送费用不计入包邮门槛。培训例：商品优惠后 US$99.99 收 US$9.95 标准运费；商品优惠后 US$100.00 免标准运费。变更前和负责人沟通，并同步审核对外政策文字。

### 6.2 配送和退回地址

覆盖美国本土 48 州及 Washington, DC；排除 Alaska、Hawaii、美国属地、国际及 APO/FPO/DPO 军邮地址。目前不提供自提或到付。

发货及批准后退回地址：

> SnowForce - Returns
> 1 Park Plaza, #600 Office 44
> Irvine, CA 92614, United States

仓库和覆盖区域在 **Settings → Locations & Shipping** 管理；日常未经负责人确认不要更改。SnowForce shipping 只调整运费和包邮门槛，不会自动修改配送州范围。

### 6.3 客服邮箱和政策

客服邮箱为 **Shop@snow-force.com**。在 **SnowForce policies → 客服邮箱** 编辑并保存草稿；正式对外变更需负责人审阅后发布政策。只保存草稿不会替换当前生效联系方式。

前台首页页脚、商城顶部、商城政策页和会员订单详情会显示完整客服邮箱。政策生效后使用当前发布版本；尚无生效政策或读取失败时显示已确认的 Shop@snow-force.com。

邮箱字段只保存联系方式，不会创建邮箱。客服邮件应通过已配置并实际可用的邮箱系统处理，不能把后台保存成功当作邮件已发送。

当前政策仍为草稿，退换货期限、商品条件、运费承担和回复正文须负责人审阅，不能提前把草稿当成已生效承诺。历史订单按下单时的购买条款处理。

## 7. 发布、下架和前台核对

### 7.1 发布前的检查

- [ ] 标题、说明、照片真实，中文及英文显示已核对。
- [ ] 每个可售颜色和尺码有唯一 SKU、正式 USD 价格和正确现货库存。
- [ ] Manage Inventory 开启，Allow backorders 关闭。
- [ ] 商品与 Irvine 仓库关联主站使用的销售渠道，配送配置正确。
- [ ] 商品税务分类已审核；经营资料及对外政策已准备完成。
- [ ] 图片上传职责已实际验收，不存在保存后前台无法显示的问题。
- [ ] 整体商城上线验收通过，负责人明确同意发布与开放经营。

**当前保持 Draft。** 发布权限存在，但不代表商城付款和经营条件已经完成。

### 7.2 正式发布后的核对

获负责人确认后，在商品状态编辑处把 **Draft** 改成 **Published**，保存。下架改回 **Draft**，保留商品及历史订单。

在实际交接的商城前台网址核对：商品能找到，详情正确，CN / EN 能切换，所选颜色与尺码的 USD 售价准确，可用库存状态正确。保存后台数据不会自动修改首页版式。

发布后没有显示，按顺序检查：Published 状态、销售渠道、具体规格价格、仓库及可用库存、前台与后台是否使用同一套配置；仍异常时把 SKU 和现象交给负责人，不重复创建另一份商品。

## 8. 订单与售后工作边界

### 8.1 当前可以做什么

熟悉 Orders 和 SnowForce returns 页面，准备商品与客服资料。当前付款关闭，没有真实订单；真实收款、退款、发货及税务冲销流程还未完成全链路验收。不要用真实资金或订单进行培训。

### 8.2 上线验收后再开展的工作

| 工作 | 操作要点 |
| --- | --- |
| 接单 | 核对正确订单、真实收款、商品规格、库存和收货地址 |
| 发货 | 建立正确商品的履约记录；自行购买面单、包装并实际交运，再保存 shipment 和追踪号 |
| 物流跟进 | 承运商确认送达后再标记 Delivered，不在打印面单时提前标记送达 |
| 退换货申请 | 在 SnowForce returns 读取申请及订单适用政策，记录回复和审核结果 |
| 审批与退款 | 批准申请不是已退款；需关联原生处理记录、核对收货和实际资金，并由指定负责人处理 |

完整交易步骤及尚未完成事项见 [商城后台使用手册](shop-admin-user-guide.md) 和 [商城上线清单](shop-launch-status.md)。这份合伙人版不把未验收的付款或退款当作已经可用。

### 8.3 发生问题时如何交接

记录商品 Handle / SKU 或订单编号、所在菜单、出现时间、页面提示、已经做过的操作和下一步；发给负责人或技术支持。不要发送密码、重置链接、Stripe 密钥、环境文件或完整顾客资料。密码问题请负责人协调现有账号的恢复方式。

## 9. 第一次上手与日常检查表

### 9.1 第一次上手

1. 与负责人完成第 1 节的实际电脑登录与保存验收。
2. 选择一款草稿，对照实物核对英文资料及图片。
3. 列出所有实际可售颜色和尺码，逐一核对唯一 SKU。
4. 填正式 USD 价格，登记正确 Irvine 现货库存。
5. 把中文资料、图片异常、渠道或税务问题交给对应负责人处理。
6. 重新打开商品确认修改已保存，记录已完成项与待确认项；当前不发布。

### 9.2 每日维护

| 时机 | 检查事项 |
| --- | --- |
| 开始工作 | 后台可访问，确认正确账号和待办；两人避免同时修改同一记录 |
| 改价以后 | 逐个 SKU 的 USD 金额正确；正式发布后前台同规格一致 |
| 入库以后 | SKU、仓库、调整后总量及预留正确；数量变化有原因记录 |
| 商品准备完毕 | 资料、中文、规格、渠道、图片和分类待办已记录，状态仍为 Draft |
| 对外信息变更 | 保存草稿并请负责人审阅，不把草稿当作已生效政策 |
| 结束工作 | 列出本日修改、待确认问题及下一位负责人，退出共享后台账号 |

日常商品、售价和库存信息保存在现有后台数据库，无需把这些内容写进代码。公网后台、API 管理功能与负责人登录后的界面均已验收，可以准备商品草稿、价格和库存；合伙人的实际操作培训与 Vercel 前台连接生效仍待完成。
