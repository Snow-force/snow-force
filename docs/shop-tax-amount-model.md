# 商城税额的分币模型与原生金额适配

更新：2026-10-02。已完成金额适配、[私有报价账本](shop-tax-quote-ledger.md) 和 [原子税费应用](shop-tax-quote-application.md)，包括安装版本原生数学与真实数据库最终回滚验证。尚未向实际顾客/正式购物车应用报价，没有调用真实 Tax Calculation API；顾客编排、成交/退款税账仍未完成，正式付款关闭。

## 已有代码

`services/commerce/src/lib/tax-quote-contract.ts` 定义可信后台输入和 Stripe Calculation 返回结构。`tax-quote-money.ts` 提供美元美分转换、优惠分配、Stripe 请求生成/返回核对、原生整单税行和政府费用构造、逐项与整单核验，以及原购买金额的逐件退款分配。

请求带完整收货地址、ship-from 地址、shipping 来源、真实数量、优惠后的整行金额、后台审核的商品分类与运费分类，标价方式为 exclusive。报价绑定购物车/客户、原生购物车 fingerprint、Stripe 账户/模式、税务配置版本、每商品分类版本/内容、价格/数量/优惠、地址及运费。税务时间另行绑定实际请求，便于后续缓存未变化的报价。报价有效期取 Stripe 到期时间与报价时间后 15 分钟的较早值。

输入仅接受既定 48 州及 DC，且需经营者/许可/义务确认和 active California 状态；当前真实经营者尚未确认，不能构造正常报价。服务端来源已从受控配置及实际 Stripe 读取这些条件，**并非已经验证真实许可或登记**。金额模型不创建这些确认；独立 writer 仅在受控条件通过后请求报价。

## 商品、优惠和税额

商品单价和实际金额使用整数美分，支持范围与 Stripe 的 8 位美元金额范围一致。百分比优惠可能产生小数美分；先按整单四舍五入的优惠金额，用余数从大到小分配给原生商品行，相同余数按稳定 ID 排序。再给每行已有优惠记录分配其目标美分，保留原生 adjustment ID。优惠不会大于商品价，前后金额必须守恒。受控归一化写回接口已实现，顾客自动调用尚未连接；不能继续使用旧的小数金额付款。

Stripe 返回的逐行 amount_tax 是税额来源，不用法定百分比重新四舍五入。每行同时保留司法辖区、法定税率与 taxability_reason；原生税行的映射百分比另行计算，只用于 Medusa 金额表达，不能作为法定税率或申报数据。每行价格、数量、优惠、净额和税额、运费税、固定费用以及整单分别核对；总额碰巧相同不能覆盖某行不匹配。

原生税表使用 REAL，当前 Shared pooler 输出精度还会将其转为六位有效数字。应用计划按 float4 映射税率，校验只接受这个具体存储税率的已知表示，并按实际读到的税率复算。计算结果与具体运算间只允许百万分之一美分残差；逐行、运费及整单四舍五入后的应付美分仍必须与报价完全相同。原商品价格、待写入优惠、运费、政府费、Stripe 和原单退款金额仍严格为整数美分。详见 [存储精度核验](shop-tax-quote-application.md)。

零税额保留明确原因。未登记的 not_collecting 只能与已审核的经营义务、完整实际注册列表对应；在声明收税州收到同类结果会停止核对。Stripe 官方说明，精确的 Nontaxable 类别也可能返回 not_collecting；只有后台明确审核选择该类别的对应商品才能按此解释，不给普通商品补这个默认类别。unsupported、未知规则、B2B reverse charge 或 customer exemption 当前停止处理。参考 [Stripe 零税额说明](https://docs.stripe.com/tax/zero-tax)。

## 固定政府费用

将合法适用且实际计算出的 CO/MN Retail Delivery Fee 与 sales tax、商家运费分开记录。核对金额、币种、州、flat_amount 类型和对应已确认的 retail-fee 登记，不写死政府费率。包邮的运费仍为 0。

候选原生表达使用独立 custom line：数量 1、实际费用单价、未含税、无税行、无优惠、is_discountable=false、requires_shipping=false；无商品/规格关联及库存。metadata 绑定 calculation ID 与报价指纹。该标签本身不能当授权凭证；后续必须由私有且签名的报价授权创建，并严格拒绝顾客伪造的标签或自定义行。

原生 item_subtotal 会包含独立费用，所以不能直接算作商品营收或包邮商品金额。私有费用证明、商品分类及包邮商品金额排除已连接；完整库存/配送流程验收、前台与 Admin 独立展示、会员订单投影和普通退换货排除仍需完成，防止重复计税。费用退款规则保存为 requires_review。参见 [Stripe Retail Delivery Fee 与详细税行](https://docs.stripe.com/tax/standalone-tax-api)。

## 部分退货仍需完整财务适配

原净额与销售税分别按原始数量分配到单位，再从累计已退数量继续取下一批。全部退完时，两项金额及总额与原单严格一致，不按新税率重算。不在此辅助函数中自动退运费或政府费用。后续需要持久保存原分配、短事务扣减剩余额度、稳定退款请求/幂等和真实 Stripe Refund 最终状态，才能创建税冲销。

实测案例：3 件商品每件 US$10.00，整行优惠 US$0.01，Stripe 原行销售税 US$1.54；原净额 2,999 美分、税额 154 美分。该原始分配的三次逐件退款为 1,052 / 1,051 / 1,050 美分，合计 3,153 美分。未修改的 Medusa 默认按比例处理，一次退 1 件会产生不同的分币分配。**候选金额代码没有解决原生退货/订单余额/Refund workflow 的这个差异。** 后续必须令真实退款、原生订单财务、税冲销和顾客收据共同匹配，而不能只用原生 pending_difference 归零判成功。
