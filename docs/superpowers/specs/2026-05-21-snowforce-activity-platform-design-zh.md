# SnowForce 活动平台设计规格

## 摘要

SnowForce 将从以介绍为主的网站升级为一个中英双语的活动运营站。
第一版需要帮助访客发现当前活动、在站内完成报名、浏览往期活动回顾，
并可选择创建轻量会员档案，让后续报名更顺畅。

第一版并不定位为完整票务系统或会员权益平台。它要先建立一套可持续扩展
的基础，便于后续加入在线支付、候补名单、会员权益、训练产品和转化分析。

## 产品形态

### 公开站点体验

- 首页以 SnowForce 品牌、真实活动视觉、当前活动入口和足够的社群信任素材
  为核心，直接支持报名转化。
- 主导航覆盖当前活动、往期回顾、关于与联系内容、合作咨询和会员入口。
- 当前活动包含活动列表页和活动详情页。
- 活动详情展示时间、地点、适合人群与水平、活动亮点、流程或注意事项、
  费用说明、名额状态、FAQ/提示内容和报名按钮。
- 往期回顾展示日期、地点、标签、短回顾，以及照片或视频媒体，方便 SnowForce
  在站内其他位置复用这些信任素材。
- 首版只保留现有网站中必要的品牌与联系信息，不迁移全部旧站长文案。

### 活动报名

- 访客不注册账号也可以报名。
- 已登录会员可以复用已保存资料报名，并在之后查看自己的报名记录。
- 每个活动可配置报名表单。默认字段包含姓名、联系方式、滑雪经验水平、
  备注和必需同意项。
- 报名提交前必须校验活动是否可报名、字段是否满足要求、同意项是否完整。
- 报名成功后展示确认状态并触发确认邮件。即使后续通知发送失败，已保存的
  报名记录也不能丢失。

### 轻量会员

- 第一版支持邮箱登录。
- 会员档案保存可复用的报名资料，并提供报名记录页面。
- 第一版不包含等级、积分、专属权益、折扣或权限规则。

### 运营后台

- 工作人员在统一后台管理活动、回顾、FAQ、媒体资源和报名记录。
- 工作人员可以创建草稿、发布活动、开放报名、关闭报名。
- 工作人员可以筛选和导出报名记录，并区分访客报名与会员关联报名。
- 双语字段需要明确维护。某语言版本缺少必需内容时，不应在该语言版本发布。

## 架构

实现上采用一个全栈 Web 应用，让公开站点、会员区域和后台共用路由、类型、
校验和数据访问层。默认技术栈为 Next.js 与 TypeScript，使用 Supabase 承载
Postgres、认证、存储和行级权限基础，并预留事务邮件适配层用于报名确认和
工作人员通知。

代码需要分离公开内容查询、报名领域逻辑、会员资料访问和工作人员后台操作。
报名服务负责活动状态校验、可配置表单校验、持久化和通知触发，这样公开页面
和未来支付流程可以复用同一套规则。

## 核心数据

- `Event`：双语内容、时间安排、地点、适合人群/难度、名额状态、发布状态、
  报名窗口、报名字段配置、媒体和 SEO 字段。
- `Registration`：活动关联、可空会员关联、表单答案、同意项记录、联系方式
  快照、报名状态和时间戳。
- `MemberProfile`：认证用户关联和可复用报名资料。
- `EventRecap`：双语回顾内容、日期、地点、标签、媒体和发布状态。
- `FAQItem`、`PartnerInquiry`、`MediaAsset`：支撑站点运营的辅助数据。

## 异常处理与安全

- 已关闭、未发布、不可用或无效活动不能接受新报名。
- 报名表单要展示可操作的校验反馈，并尽量保留用户已输入内容。
- 公开提交接口必须具备防垃圾提交的默认措施和服务端校验。
- 后台操作必须要求工作人员权限。
- 通知失败需要可记录、可追踪，同时让已保存报名仍对后台可见。

## 验收标准

- 工作人员可以发布一个双语当前活动和一个双语往期回顾。
- 访客可以从首页找到活动，在站内完成报名，并看到清晰确认结果。
- 会员可以用邮箱登录、维护档案、复用资料报名，并查看报名记录。
- 工作人员可以在后台查看、筛选、更新和导出报名记录。
- 公开页面在移动端和桌面端都可用，且活动报名入口明显。

## 暂缓范围

- 在线支付、退款和发票。
- 候补名单及名额递补流程。
- 会员权益、忠诚度成长和专属访问规则。
- 超出活动元数据之外的训练/课程产品专门化。
- 高级转化分析、优惠码和日历集成。
