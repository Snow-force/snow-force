# 商品税务分类管理

更新：2026-10-02。这是正式计税接入的前置配置；不是已完成的销售税引擎或申报系统。

## 日常操作

登录 [商城后台](http://127.0.0.1:9000/app/snowforce-tax)，打开 **SnowForce product tax**。从原生商品列表选择草稿或已发布商品，点击加载 Stripe 官方分类，搜索分类名称、说明或完整代码。核对官方说明适用于该商品所有颜色、尺码和规格，填写审核依据后确认保存。

分类由商城环境的 Stripe Tax Codes API 实时读取完整分页，并在保存时再次 GET 核实选中的精确代码。代码是官方不透明标识；系统不根据商品标题猜测、不自动选分类、不补默认免税分类。接口失败时停止保存。需要 performance location 的分类、未知新增的此项要求以及礼品卡当前不支持。分类选择及免税依据由经营者/申报负责人审核，系统不代替法律判断。参考 [Stripe 分类说明](https://docs.stripe.com/tax/tax-codes) 和 [Tax Codes API](https://docs.stripe.com/api/tax_codes/list)。

首版商品价格为未含税美元，审核记录的 tax_behavior 固定为 exclusive，与既定标价方式一致；没有按州写死税率。相同商品全部规格共用一个类别，不支持混合税务类别的组合商品。后台审核依据应写明商品性质及依据，不能仅凭名字分类。

## 数据方案与变更

配置保存在原有 Supabase PostgreSQL 私有 `commerce.store.metadata.snowforce_tax_classifications`，按原生 product ID 分开保存。只有现有商城管理员/API 能读取；**不放在 Store API 会返回的 Product metadata**。继续使用 `snowforce_commerce` 专用角色，没有新增数据库、表、迁移、授权或登录系统。

每次审核保存完整的官方代码/名称/说明、exclusive 标价方式、商品内容 fingerprint、依据、原生管理员 ID、数据库时间、递增版本及请求回执。商品原生名称、副标题、描述、类型、材质、HS code、原产地，以及规格的数量、ID、名称、材质、HS code、原产地变化后，原审核失效。商品从 draft 发布，以及改变价格或库存不修改分类 fingerprint；金额变化将由后续税额报价校验处理。

保存采用预期版本和内容 fingerprint，Stripe 只读请求放在数据库事务外。事务内重读并锁住唯一 Store 和商品行，只修改对应分类键，保留商品、库存、运费、政策及其他商品的设置。同一请求 UUID 重试不追加历史；同一 UUID 改变内容或管理员身份会拒绝。未知保存结果时后台锁住编辑并用同一请求重试。完整历史追加保留，每商品上限 100 次审核；达到上限会停止新增记录，需先另做经审阅的审计归档/迁移，不静默删除历史。

目前 14 件真实商品仍为草稿且尚无实际分类审核。经营者可在后台自行填写；这次没有自动为任何真实商品指定类别。

## 结账保护和剩余工作

商城准备付款、准备阶段的购物车锁内，以及原生完成订单 hook 均核对原生购物车商品与规格。缺失、过期审核，删除/自定义商品、非发布商品、礼品卡、需要额外活动地点信息的类别、未来审核时间、读取错误都停止付款。读取结账页时只将未准备状态反映到 configured，不把分类依据或管理员记录给顾客。取消付款的只读恢复仍可用。

此核验只证明分类前置条件，**不证明已有准确税额**。后续仍须将该审核版本/分类指纹纳入签名且不可变的 Tax Calculation 报价，接入运费分类、完整地址、注册验证、逐行分币及政府费用表达、私有税务账本和捕获/退款冲销。单独改变分类或确认许可证，均不能跳过这些验收。`COMMERCE_TAX_POLICY_CONFIRMED` 当前为 false，正式收税和付款仍关闭。

## 实际验收

- 真实专用角色与 CA 验证 TLS 连接通过。Stripe 只读 API 返回完整 677 个官方分类；没有创建 Tax Calculation、税务登记、交易、付款或退款。
- 在真实数据库的回滚事务内验证分类写入、同 UUID 重试、旧版本冲突、其他 Store metadata 保留；回滚后整份 metadata 完全相同，14 草稿、0 发布商品、0 订单、0 付款。
- 两个指定管理员分别读取新接口为 200/14 件；无效 offset、未确认的保存为 400；匿名为 401。实际 React 18 页面测试覆盖选择/审核、保存、失败重试、冲突重载和错误返回目标。
- 实际税款、真实订单/分类保存及完整支付端到端流程尚未执行。核验结果为 [脱敏数据库与 HTTP 记录](../output/shop-tax-classification-live.json)。
